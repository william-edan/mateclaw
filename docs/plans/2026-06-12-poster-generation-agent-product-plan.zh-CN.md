# 海报生成 Agent 产品总计划：个人版先行，团队版演进

最后更新：2026-06-12

## 1. 执行摘要

MateClaw Poster Agent 应采用“两阶段产品路径”：先做个人版，验证生成质量、易用性和个人付费意愿；再在真实使用数据和付费用户需求基础上，演进团队版和企业版。

这个能力的付费逻辑是：

> 先帮助个人创作者、小商家、运营人员和自由职业者快速生成可发布的营销海报；再帮助团队以更低设计周转成本，持续生成符合品牌规范、可审核、可复用、可追溯的营销物料。

个人用户先为“效果好、上手快、能直接发布”付费。团队和企业后续为“品牌一致性、素材治理、模板复用、审批流程和生产可追踪”付费。

易用性必须作为产品能力的一部分，而不是界面细节。个人版尤其要让非设计人员也能完成常规海报生产：少输入、少选择、少犯错、结果可解释、修改路径清晰。团队版在此基础上增加品牌治理、协作和审批。

因此，V1 应定义为：

> 面向个人和小商家的营销竖版海报生成 Agent，同时预留团队版的品牌资产、素材库和版本化协议。

V1 不是完整 DAM，不是完整设计编辑器，也不是团队协作平台。V1 是第一个能证明产品价值的生产级切片：个人用户可以输入 Brief、上传 Logo/二维码/商品图，生成海报候选，保留关键文字，进行基础质量检查，导出结果，并保存历史版本。团队版能力从 V2 开始系统化建设。

## 2. 产品定位

### 2.1 不应该定位成什么

这个产品不应该定位成：

- `image_generate(prompt)` 的简单包装。
- 一次性海报生成器。
- 个人设计小工具。
- ChatGPT 图片生成的低价替代品。
- 让海报更好看的 Prompt 模板库。
- 一开始就很重的企业 DAM 或审批系统。

这些方向容易被复制，也很难形成企业付费理由。

### 2.2 应该定位成什么

这个产品应该定位成：

- 个人版：面向创作者、小商家、运营人员的高质量海报生成 Agent。
- 团队版：面向团队的品牌一致性创意助手。
- 结构化海报生产工作流。
- 品牌资产、模板、生成模型和审批流程之间的连接层。
- MateClaw 内部可复用的内容生产系统。

真正的长期壁垒不是某个图片模型，而是先从个人使用中沉淀可复用的生成链路，再逐步升级为团队创意上下文：

- 个人品牌配置。
- 个人素材库。
- 模板和历史作品。
- 活动 Brief。
- 审批策略。
- 质量评估数据。
- 使用历史。
- 版本化海报规格。
- 团队工作流集成。

## 3. 产品版本拆分

### 3.1 个人版

个人版是第一阶段产品，目标是验证海报生成能力能否真正让用户付费。

目标用户：

- 自媒体创作者。
- 小红书/朋友圈运营人员。
- 小商家。
- 课程、活动、社群运营者。
- 自由职业设计辅助用户。
- 中小企业中没有专职设计支持的一线人员。

核心价值：

- 一句话生成可发布营销海报。
- 不需要学习 Prompt。
- 不需要从空白画布开始。
- 标题、价格、日期、CTA 等关键文字准确。
- 可上传个人 Logo、二维码、商品图和参考图。
- 可复用个人历史风格和模板。
- 可导出高清图片。

个人版 V1 成功标准：

- 用户能在 3 分钟内从 Brief 得到可用海报。
- 70% 以上评测 Brief 的输出达到“可直接发布或轻微修改可发布”。
- 用户愿意为高清导出、更多生成额度、更多模板、去水印或历史版本付费。
- 收集到足够多的团队版需求，例如多人协作、品牌统一、共享素材、审批和权限。

### 3.2 团队版

团队版是第二阶段产品，建立在个人版验证成功之后。

目标用户：

- 中小企业市场团队。
- 连锁门店运营团队。
- 教育/培训机构。
- SaaS 和 B2B 营销团队。
- 本地生活服务商家。
- 品牌方和代理商。

核心价值：

- 团队共享 Brand Kit。
- 团队共享素材库和模板库。
- 不同成员生成结果保持品牌一致。
- 管理员能控制 Logo、字体、颜色、禁用词、授权素材。
- 导出、审批、版本和素材使用可追踪。

团队版成功标准：

- 一个团队能配置并复用 Brand Kit。
- 多个成员生成的海报风格一致。
- 管理员能查看使用了哪些素材、谁导出了什么版本。
- 团队愿意为席位、品牌数量、素材库、审批和批量生产付费。

### 3.3 为什么要先做个人版

先做团队版会引入大量重能力：权限、审批、资产治理、组织模型、素材授权、审计日志、管理员界面。这些能力很重要，但在生成质量和个人付费未验证前过早建设，容易导致周期长、反馈慢、产品变重。

个人版先行的好处：

- 更快验证核心生成质量。
- 更快验证用户是否愿意付费。
- 更快收集真实 Brief、模板偏好和失败案例。
- 更容易打磨易用性。
- 为团队版积累模板、质量评测和素材工作流。
- 从付费个人用户中识别团队客户线索。

## 4. 为什么个人和团队会付费

### 4.1 个人版付费锚点

个人版的付费理由更直接：

- 生成效果比通用图片工具更适合营销海报。
- 文字准确，不需要反复修标题、价格、日期、CTA。
- 模板和版式稳定，能直接用于小红书、朋友圈、课程、活动和促销。
- 上传 Logo、二维码、商品图后能得到更接近真实发布场景的结果。
- 高清导出、去水印、更多生成额度、更多模板和历史版本值得付费。
- 对话式修改比传统设计工具更容易上手。

个人版不是弱化版企业产品。它应该独立成立，并承担三个任务：验证生成质量、验证易用性、验证付费意愿。

### 4.2 团队版付费锚点

团队版的付费理由建立在个人版成功之后：

- 品牌一致性。
- 素材资产治理。
- 模板复用。
- 团队协作与审批。
- 多渠道生产。
- 合规与风险控制。
- 数据分析与持续优化。
- 安全、权限和部署。

### 4.3 品牌一致性

企业不希望每个员工生成出的海报都像不同品牌。系统必须能维持公司统一识别：

- Logo 使用方式。
- 品牌色。
- 字体。
- 品牌语气。
- 版式规则。
- 禁用视觉风格。
- 安全区。
- 必需免责声明。

付费理由：营销负责人希望让更多员工参与内容生产，但不能牺牲品牌控制。

### 4.4 素材资产治理

团队通常已经有很多素材：产品图、客户案例、二维码、背景图、图标、奖章、证书、人物照片、活动图等。

系统需要管理：

- 素材来源。
- 授权状态。
- 授权过期时间。
- 允许使用的渠道。
- 负责人。
- 审批状态。
- 使用历史。

付费理由：企业担心用错素材、误用过期活动图、使用未授权图片，或者二维码不一致。

### 4.5 模板复用

企业需要的是可重复生产，而不是每次从空白画布开始。

模板系统应支持：

- 官方模板。
- 企业模板。
- 行业模板。
- 活动模板。
- 历史高表现模板。
- Logo、二维码、标题、价格、CTA、法律文本等锁定区域。

付费理由：模板能把“生成能力”变成“生产线”。

### 4.6 团队协作与审批

商业内容通常存在不同角色：

- 创建者。
- 审核者。
- 品牌负责人。
- 法务/合规审核者。
- 管理员。

系统应支持：

- 版本历史。
- 导出记录。
- 审核状态。
- 审批意见。
- 人工复核兜底。
- 审计日志。

付费理由：团队需要可控发布，而不是任意生成、任意导出。

### 4.7 多渠道生产

一次营销活动往往需要多种素材：

- 小红书竖版海报。
- 朋友圈海报。
- 公众号封面。
- 抖音封面。
- 视频号封面。
- 销售赋能海报。

V1 可以先从 1080x1920 竖版海报开始，但产品架构必须为后续多尺寸、多渠道生成预留空间。

付费理由：企业购买的是更快的内容供应能力。

### 4.8 合规与风险控制

营销海报可能带来法律、品牌和声誉风险。

系统应提示：

- 广告绝对化用语。
- 医疗、金融、教育、投资、功效承诺等高风险表达。
- 缺失免责声明。
- 未授权素材。
- AI 生成图片来源。
- 用户上传版权素材风险。

付费理由：很多企业不是不能生成内容，而是不敢随便发布内容。

### 4.9 数据分析与持续优化

系统应帮助团队了解：

- 哪些模板审核通过最快。
- 哪些 Prompt 容易失败。
- 哪些风格最容易产出可用结果。
- 哪些渠道使用了哪些素材。
- 哪些品牌规则经常被违反。
- 哪些模型成本高或稳定性差。

付费理由：企业愿意为可度量的流程效率提升付费，而不是为一次性新鲜感付费。

### 4.10 安全与部署

对商业客户而言，系统后续需要支持：

- 团队数据隔离。
- 角色权限。
- 审计日志。
- 可配置模型提供商。
- 可选私有化部署。
- SSO。
- 素材访问控制。

付费理由：真实客户需要信任、治理能力和采购兼容性。

### 4.11 易用性与采用率

企业采购后能不能真正用起来，取决于一线人员是否能低成本完成任务。

系统必须降低以下门槛：

- 不要求用户懂 Prompt。
- 不要求用户懂设计术语。
- 不要求用户知道该选什么模型。
- 不要求用户从空白画布开始。
- 不要求用户理解复杂图层结构。
- 不要求用户反复试错才能得到可用结果。

产品应提供：

- Brief 向导：用少量问题补齐平台、目标人群、卖点、CTA、素材。
- 智能默认值：没有完整品牌信息时给出安全默认值，并标记 `brand_incomplete`。
- 模板推荐：根据场景自动推荐模板，而不是让用户面对完整模板库。
- 候选对比：默认生成 2 个候选，并突出差异点。
- 可解释质量状态：告诉用户为什么 `passed`、`needs_manual_review` 或 `failed`。
- 一键修复：对文字太小、对比度不足、Logo 被裁切等常见问题给出直接操作。
- 渐进披露：普通用户只看到必要选项，高级用户再展开品牌、素材、模板和合规设置。

付费理由：企业买的是团队可采用的生产系统，不是只会给专家使用的复杂工具。

这些参考不是实现依赖，而是说明成熟创意生产产品如何定义问题。

- Bynder 围绕 DAM、AI 辅助、授权和生命周期治理组织企业素材能力：<https://www.bynder.com/en/products/ai/> 和 <https://support.bynder.com/hc/en-us/articles/21576746100114-What-are-Advanced-Rights>
- Typeface 将企业生成式 AI 定位在品牌个性化营销工作流：<https://www.typeface.ai/>
- Figma 团队库展示了共享组件、样式、变量和设计系统如何保持团队一致性：<https://help.figma.com/hc/en-us/articles/360041051154-Guide-to-libraries-in-Figma>

## 6. 创意上下文层：从个人到团队

产品的核心层应定义为可演进的 `CreativeContext`。

个人版先组装 `PersonalCreativeContext`，团队版再升级为 `EnterpriseCreativeContext`。每一次海报生成，都应该先组装上下文，再进行模型提示词生成、图片生成和最终渲染。

### 6.1 核心对象

- `Account`：个人用户边界。
- `Workspace`：团队版中的公司或团队边界，V1 仅预留。
- `PersonalBrandProfile`：个人版中的品牌名、Logo、颜色、常用语气、常用二维码。
- `BrandKit`：团队版中的品牌名、Logo、颜色、字体、语气、视觉风格、禁用风格。
- `BrandGuideline`：可执行品牌规则，例如 Logo 安全区、最小对比度、必需免责声明、禁用词。
- `AssetLibrary`：已审批 Logo、产品图、二维码、背景图、图标、客户照片、证书、案例图。
- `TemplateLibrary`：官方模板、企业模板、行业模板、已审批活动模板。
- `CampaignBrief`：活动目标、目标人群、优惠、产品、活动时间、CTA、渠道。
- `ComplianceRules`：广告风险词、行业限制、必需免责声明、人工复核触发条件。
- `ApprovalPolicy`：团队版中谁可以生成，谁可以导出，什么情况下必须审批。
- `UsageAnalytics`：生成次数、导出次数、通过率、成本、耗时、模板使用情况。
- `VersionHistory`：海报版本、修改、审批、导出和回滚元数据。

### 6.2 核心原则

个人风格和企业风格都不能只存在于 Prompt 中。

它必须同时存在于：

- 可检索的资产。
- 可执行的约束。
- 可复用的模板。
- 质量检查。
- 审计记录。
- 审批策略。

## 7. 产品架构

### 7.1 品牌中心

职责：

- 个人版管理 Personal Brand Profile，团队版管理 Brand Kit。
- 存储 Logo、颜色、字体、语气和视觉偏好。
- 团队版定义禁用视觉风格和禁用文案。
- 定义 Logo、二维码、法律文本、产品图的使用规则。
- 向 Poster Agent 提供品牌上下文。

V1 应实现个人版最小版本，不做完整品牌门户。

### 7.2 素材库

职责：

- 存储并分类个人素材。
- 跟踪来源和使用记录。
- 提供素材搜索与选择。
- 团队版再默认阻止使用过期或未审批素材。
- 记录每个海报版本使用了哪些素材。

V1 应支持 Logo、二维码、商品图、背景/参考图。

### 7.3 模板库

职责：

- 存储海报模板。
- 按场景、渠道、行业、品牌兼容性标记模板。
- 支持 Logo、标题、二维码、CTA、价格、法律文本等锁定槽位。
- 跟踪模板使用量和质量分。

V1 至少应包含三类模板：

- 卖点价值型海报。
- 活动/课程报名型海报。
- 产品促销型海报。

### 7.4 海报 Agent

职责：

- 理解用户 Brief。
- 增强缺失的营销信息。
- 尊重用户提供的锁定文字。
- 选择模板。
- 生成无文字主视觉。
- 确定性合成最终海报。
- 执行质量检查。
- 生成候选版本。
- 支持对话式修改。

### 7.5 质量与评估层

职责：

- 使用 OCR/VLM 检查必需文字。
- 检查品牌色、Logo 和安全区。
- 检查重叠、安全边距、对比度和可读性。
- 检查合规风险。
- 检查素材来源。
- 支持生成回归评测。

V1 应先实现确定性检查，并在可用时使用 OCR/VLM。

### 7.6 审批与历史

职责：

- 保存海报版本。
- 保存质量状态。
- 保存导出记录。
- V1 保存人工复核状态。
- 团队版再保存审批状态和审批意见。

V1 可以保持轻量，但数据模型中必须存在这些概念。

### 7.7 易用性设计层

职责：

- 将复杂的品牌、模板、素材和合规配置包装成简单任务流。
- 个人版先提供创建者视图，团队版再提供审核者和管理员视图。
- 在生成前提示缺失信息，但不阻断低风险场景。
- 在生成中展示进度、预计步骤和失败原因。
- 在生成后提供候选对比、质量解释和下一步操作。
- 支持撤销、重新生成、复制为新版本和基于当前版本继续修改。

V1 应至少支持：

- 单页 Brief 输入体验。
- 自动模板推荐。
- 候选海报并排预览。
- 明确的质量状态和问题说明。
- 常见问题的一键修复入口。
- 生成失败时给出可操作原因，而不是只显示失败。

## 8. V1 定义

### 8.1 V1 目标

V1 要证明 MateClaw 能为个人用户和小商家稳定生成可发布的营销竖版海报，并为后续团队版预留数据和协议基础。

用户体验应是：

1. 个人用户进入海报生成入口。
2. 用户输入营销 Brief。
3. 用户可选 Logo、二维码、商品图、参考图或历史风格。
4. Agent 生成两个 1080x1920 海报候选。
5. 系统保留锁定文字和个人品牌资产。
6. 系统检查文字、版式、二维码、Logo 和基础合规风险。
7. 结果作为带版本、可追溯的个人海报资产保存。

### 8.2 V1 必须包含

- 个人账号关联，数据结构预留未来 `workspaceId`。
- 最小 `PersonalBrandProfile`，包含品牌名、Logo、主色、常用二维码和常用语气。
- Logo、二维码、商品图、背景/参考素材选择。
- 三类个人/小商家营销模板。
- 版本化 `PosterSpec`。
- 对品牌名、标题、副标题、价格、日期、免责声明、CTA 的锁定文字处理。
- 易用的 Brief 输入体验，避免用户必须学习 Prompt 写法。
- 自动模板推荐和安全默认值。
- 候选对比视图，便于用户快速选择可用版本。
- 可解释质量状态和下一步建议。
- 确定性文字和版式渲染。
- 用于主视觉的无文字图片生成。
- 品牌色和 Logo 检查。
- 素材来源记录。
- 基础广告风险提示。
- 生成历史和版本记录。
- 导出记录。
- 质量状态：`passed`、`needs_manual_review`、`failed`。

### 8.3 V1 可选但建议包含

- 人工审核备注。
- 模板使用统计。
- Prompt/模板版本字段。
- 质量检查失败时的一次自动修复。
- 高层级成本和耗时记录。
- 常见编辑意图快捷入口，例如“标题更醒目”、“更换风格”、“保留文字重新生成主视觉”。

### 8.4 V1 不包含

- 完整 DAM。
- 完整在线设计编辑器。
- 复杂多级审批流。
- 私有化部署。
- 对外商业 API。
- 投放效果回传。
- A/B 测试。
- 完整多渠道尺寸适配。
- 内置 ComfyUI。
- 复制 GPL/AGPL 项目代码或内置非商用模型权重。
- 团队 Workspace 管理。
- 多人协作。
- 团队共享素材库。
- 团队审批和权限。

## 9. V1 生成链路

### 9.1 Brief 输入

输入包括：

- 用户自然语言 Brief。
- 可选平台。
- 可选模板偏好。
- 可选 `personalBrandProfileId`。
- 可选历史风格或历史作品 ID。
- 可选素材 ID。
- 可选参考图 ID。

系统应将这些输入归一化为结构化 Brief。

### 9.2 个人品牌上下文组装

系统应加载：

- Personal Brand Profile。
- 个人素材。
- 可用个人风格规则。
- 候选模板。
- 合规规则。
- 历史生成上下文。

如果没有 Personal Brand Profile，则使用安全默认值，并提示用户后续可通过保存 Logo、二维码、主色和常用语气提升一致性。团队版再引入严格的 `brand_incomplete` 状态。

### 9.3 输入增强

增强器应推断或补齐：

- 场景。
- 目标人群。
- 优惠或利益点。
- 核心卖点。
- CTA。
- 语气。
- 视觉方向。
- 必需文字。
- 禁用文字。
- 海报中缺失但有价值的信息。

增强器不得改写用户提供的锁定内容。

### 9.4 模板选择

系统应根据以下信息选择已审批模板：

- 场景。
- 平台。
- 品牌兼容性。
- 素材可用性。
- 文本量。
- 是否需要二维码、价格或活动信息。

### 9.5 主视觉生成

主视觉 Prompt 应明确排除文字和 Logo，除非这些元素后续会以受控参考素材方式合成。

模型输出应作为视觉素材，而不是最终海报的文字排版结果。

### 9.6 确定性合成

海报中的文字、Logo、二维码、价格、日期、免责声明和 CTA 必须由确定性渲染器渲染。

这是必要条件，因为图片模型仍然无法稳定生成精确商业文字。

### 9.7 质量检查

检查项应包括：

- 必需文字是否出现。
- 锁定文字是否未被篡改。
- 重要文字是否可读。
- 文本对比度是否合格。
- 是否存在严重重叠。
- Logo 是否变形或被裁切。
- 二维码是否被遮挡。
- 品牌色使用是否在允许范围内。
- 素材使用是否被允许。
- 是否存在基础合规风险。

当 OCR/VLM 不可用时，结果应标记为 `needs_manual_review`，不能伪装成检查通过。

### 9.8 自动修复

V1 应支持一次自动修复：

- 调整字号。
- 提升对比度。
- 移动重叠图层。
- 添加遮罩或文字背景板。
- 切换到更稳妥模板。

只有当主视觉明显偏题或不可用时，才重新生成主视觉。

## 10. PosterSpec 作为产品协议

`PosterSpec` 应被视为版本化产品协议，而不是普通内部 JSON。

它应记录：

- 画布尺寸。
- 平台。
- 模板 ID 和版本。
- 品牌 ID 和版本。
- 图层树。
- 文字图层。
- 图片图层。
- 形状图层。
- 二维码图层。
- 锁定图层。
- 安全区。
- 约束。
- 素材引用。
- 模型与 Prompt 元数据。
- 渲染元数据。
- 质量元数据。

这个协议支撑：

- 确定性渲染。
- 版本历史。
- 未来可视化编辑。
- 模板复用。
- 质量评估。
- 导出复现。

## 11. 商业化包装

### 11.1 Free / Trial

目的：让个人用户快速体验生成效果。

限制：

- 只支持默认模板。
- 较低生成额度。
- 不支持个人品牌长期记忆或仅支持有限记忆。
- 不支持高清批量导出。
- 导出质量受限、带水印或有数量限制。

### 11.2 Personal Pro

目的：个人创作者、小商家和运营人员付费使用。

包含：

- 个人品牌配置。
- 个人素材库。
- 更多高质量模板。
- 高清导出。
- 去水印。
- 更高月度生成额度。
- 历史版本。
- 常用二维码、Logo、商品图保存。
- 基础质量检查和一键修复。

### 11.3 Team

目的：由个人付费用户或小团队升级而来。

包含：

- Workspace。
- 团队 Brand Kit。
- 团队共享素材库。
- 团队模板。
- 成员席位。
- 基础权限。
- 基础审批状态。
- 版本历史。

### 11.4 Business / Enterprise

目的：中小企业主力套餐。

包含：

- 多个 Brand Kit。
- 多个团队空间。
- 素材来源和授权字段。
- 模板审批。
- 合规规则。
- 批量生成。
- 多渠道尺寸。
- 使用统计。
- 基础 API。
- SSO。
- 审计日志。
- 可选私有化部署。
- 专属模型路由。
- 自定义合规规则。
- DAM/CRM/商品库集成。
- 高级审批流。
- SLA。
- 定制行业模板包。

## 12. 收费模型

不要只按 token 或图片生成次数收费。

推荐采用组合收费：

- 个人版：按月/年订阅 + 生成额度 + 高清导出 + 去水印 + 高级模板。
- 团队版：按席位收费，覆盖团队成员、管理员、审核者。
- 按生成额度收费：图片生成、高清导出和批量生成。
- 按 Brand Kit 数量收费。
- 按素材存储容量收费。
- 按高级工作流能力收费，例如审批、批量、多渠道尺寸。
- 按行业模板包收费。
- 按私有化部署和 SLA 收费。

个人版价值表达应围绕“更快生成可发布海报”。团队版价值表达应围绕品牌控制、流程效率和资产治理。不要只围绕模型调用或 token 定价。

## 14. 工业级验收标准

V1 不能因为“生成了一张好看的图”就算通过。

它应在以下条件满足时验收：

- 个人用户可以配置或保存 Personal Brand Profile。
- 用户上传的 Logo、二维码、商品图能稳定进入海报。
- 用户可以在 3 分钟内从 Brief 得到候选海报。
- 关键文字被准确保留。
- Logo 和二维码不变形、不被裁切。
- 素材使用可追溯。
- 生成结果具有质量状态。
- 导出行为被记录。
- 内部评测集中至少 70% 输出可直接发布或只需轻微修改即可发布。
- 当视觉服务可用时，OCR/VLM 对必需文字的召回率目标达到 95%。
- 严重重叠、裁切或对比度失败率低于 10%。
- 系统能解释为什么某次生成被标记为 `needs_manual_review` 或 `failed`。
- 个人版出现明确付费信号，例如高清导出、去水印、更多额度或高级模板转化。
- 系统能收集团队版需求线索，例如共享素材、多人使用、品牌统一、审批和权限。

## 16. 风险与缓解

### 风险：产品变成通用图片工具

缓解：

- 把 Personal Brand Profile、素材使用和 PosterSpec 放进核心链路。
- 不让 V1 变成 Prompt-to-Image 包装器。

### 风险：输出好看但不可用

缓解：

- 确定性文字渲染。
- 锁定内容。
- OCR/VLM 检查。
- 版式检查。
- 人工复核兜底。

### 风险：过早做重团队能力

缓解：

- V1 先验证个人版生成质量、易用性和付费意愿。
- 团队 Workspace、共享素材库、审批和权限放到 V2+。
- V1 数据结构预留未来 `workspaceId`，但不提前做完整团队产品。

### 风险：个人素材被误用或丢失来源

缓解：

- 跟踪素材来源和使用记录。
- 用户上传素材默认只在个人账号范围内使用。
- 团队版再引入审批状态、授权状态和过期控制。

### 风险：范围过快膨胀

缓解：

- V1 聚焦营销竖版海报。
- 推迟完整编辑器、DAM、批量生产和多渠道活动管理。

### 风险：功能完整但太难用

缓解：

- 采用任务流优先，而不是配置项优先。
- 默认自动选择品牌、模板、尺寸和模型。
- 高级设置渐进披露。
- 每一步都提供清晰状态、问题原因和下一步建议。
- 为非设计人员提供常用修改快捷操作。

### 风险：开源许可证污染

缓解：

- 只借鉴架构思想。
- 不复制 GPL/AGPL 实现代码。
- 不内置非商用模型权重。
- 将 ComfyUI 作为后续可选外部集成。

## 17. MateClaw 实现提示

当前 MateClaw 已经有一些可复用基础：

- 基于 StateGraph 的 Agent 运行时。
- 内置图片生成工具和提供商层。
- HTML 图片渲染工具。
- Vision/OCR 服务。
- Skills 和工具绑定机制。
- 审批与渠道基础设施。
- Workflow 和 Trigger 基础设施。

推荐的 V1 实现方向：

- 新增 poster 领域包，不要过度改造通用图片工具。
- 复用 `ImageGenerationService` 生成主视觉。
- 抽取或复用确定性 HTML/SVG 渲染能力生成最终 PNG。
- 可用时使用 `ImageVisionService` 做 OCR/VLM 质检。
- 持久化 `PosterSpec`、预览图、Prompt 元数据、质量结果和素材使用记录。
- 暴露 `PosterGenerateTool`，支持 `generate`、`edit`、`status`、`templates` 动作。

## 18. 最终产品原则

产品应优先优化企业信任和团队采用率，而不是新奇感。

真正重要的体验不是：

> 我输入一个 Prompt，得到一张好看的图。

而是：

> 我的团队可以持续生成品牌一致、可审核、可追溯的营销海报，不必每个常规需求都等待设计排期。

最终体验应让普通业务人员觉得“我知道该怎么开始，也知道失败时该怎么改”，让管理员觉得“我能控制品牌、素材和风险”。
