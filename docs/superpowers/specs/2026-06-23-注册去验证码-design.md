# 注册去短信验证码 · 设计文档

- 日期：2026-06-23
- 分支：`claude/clever-hoover-52c9f8`
- 状态：待评审

## 背景

当前手机号注册（`POST /api/v1/auth/register`）强制走短信验证码：前端先点"获取验证码"调 `POST /api/v1/auth/send-register-code` 发码，用户填入 6 位码后提交，后端用 `VerificationCodeService.verifyAndConsume()` 一次性校验消费。整套短信能力（发码限流、内存存储、阿里云发送器）是 2026-06-22 才接入的（见 `2026-06-22-注册短信验证码对接阿里云-design.md`）。

现在要简化注册：**去掉验证码，手机号 + 密码直接注册，密码填两次做一致性确认。**

## 目标

- 注册只需：手机号、密码、确认密码（、可选昵称）。
- 不再发送 / 校验短信验证码。
- 密码两次输入一致性校验（仅前端）。
- 密码最少 6 位（前后端都校验）。

## 非目标（Out of Scope）

- 不删除短信验证码模块代码，仅"标记弃用 + 注册流程停止调用"，方便日后做"可选验证码"开关。
- 不改登录流程。
- 不改密码加密方式（仍 BCrypt）、不改账号 30 天过期、不改工作空间自动创建逻辑。
- 不引入新的密码复杂度规则（大小写/符号等），只加最小长度 6。

## 已确认决策

1. **短信基础设施** → 保留代码、标记 `@Deprecated`。`send-register-code` 接口、`VerificationCodeService`、`InMemoryVerificationCodeStore`、`AliyunSmsCodeSender`、`SmsProperties` 全部保留；注册流程不再调用验证码。
2. **确认密码校验** → 仅前端。后端 `RegisterRequest` 不加 `confirmPassword` 字段，后端只收 `password`。
3. **密码强度** → 最少 6 位，前后端都校验。

## 一、后端改动（mateclaw-server）

### 1.1 `model/RegisterRequest.java`
删除 `code` 字段，仅保留 `phone / password / nickname`。

### 1.2 `service/AuthService.java` · `register()`（行 72-120）
- **删除**对验证码服务的依赖与调用：
  - 删除 `verifyAndConsume(phone, request.getCode())`（行 91）。
  - 删除 `try/catch` 中"验证码已消费但注册失败 → `releaseSendLock()`"补偿块（行 93、115-119），register 体回归为顺序执行（DuplicateKey 仍就地映射为 409）。
  - 删除字段 `private final VerificationCodeService verificationCodeService;`（行 45）及对应 import（行 19）。AuthService 不再依赖短信模块；`VerificationCodeService` bean 仍由 `AuthController` 持有（发码接口用）。
- **新增**密码长度校验，放在原"密码非空"检查之后：
  ```java
  if (request.getPassword() == null || request.getPassword().isBlank()) {
      throw new MateClawException("err.auth.password_required", 400, "Password is required");
  }
  if (request.getPassword().trim().length() < 6) {
      throw new MateClawException("err.auth.password_too_short", 400, "密码长度至少6位");
  }
  ```
  （沿用现有 `MateClawException(msgKey, httpStatus, msg)` 风格；空密码仍返回既有 `err.auth.password_required`，短密码用新 key `err.auth.password_too_short`。）
- 方法 Javadoc（行 72）更新：去掉"经 VerificationCodeService 校验并一次性消费"措辞。

### 1.3 `controller/AuthController.java`
- `/register`、`/login` 不变。
- `sendRegisterCode()`（行 53-65）方法上加 `@Deprecated` + 注释："注册已不再需要验证码，保留以便日后做可选验证码开关。" 接口签名、实现、`@PostMapping` 全部保留可用。

### 1.4 短信模块其余文件
`VerificationCodeService` / `InMemoryVerificationCodeStore` / `AliyunSmsCodeSender` / `SmsProperties` / `SendCodeRequest` 原样保留，不改。

- **删除**两个纯验证码用例：`registerRejectsInvalidVerificationCode`（行 139-152）、`registerRejectsMissingVerificationCode`（行 154-167）。
- `registerMapsDuplicateKeyRaceToUsernameExists`（行 220-232）：删除末行 `verify(verificationCodeService).releaseSendLock(...)`（补偿逻辑已移除）。

### 2.3 i18n（`i18n/locales/zh-CN.ts`、`en-US.ts`，login 段）

## 三、错误与边界

| 场景 | 前端 | 后端 |
|------|------|------|
| 手机号空/格式错 | input `required` + 后端兜底 | `err.auth.invalid_phone` 400 |
| 密码空 | `required` | `err.auth.password_required` 400 |
| 密码 < 6 位 | `passwordTooShort` 提示，不提交 | `err.auth.password_too_short` 400（兜底） |
| 两次密码不一致 | `passwordMismatch` 提示，不提交 | —（后端不校验确认密码） |
| 手机号已注册 | 显示后端 msg | `err.auth.username_exists` 409 |

后端始终对密码长度兜底校验，防止绕过前端直接打接口。

## 四、风险与说明

- **安全权衡**：去掉验证码后注册门槛降低（可批量注册）。本次按需求执行；短信模块保留为日后可快速恢复"可选验证码"留口。
- **死代码**：后端短信模块短期内无人调用（仅保留的发码接口），属有意保留，已 `@Deprecated` 标注。
